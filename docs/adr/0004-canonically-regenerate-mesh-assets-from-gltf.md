# Canonically regenerate mesh assets from glTF

Refining ADR 0003, every glTF asset creation canonically regenerates the whole immutable mesh asset from artist-visible glTF state plus typed authoring inputs that glTF cannot represent. EarthTool metadata retains only those typed values and binds them through strict canonical authoring identifiers; it does not preserve exact source representations, compatibility anomalies, unclassified representations, projection fingerprints, or interchange scope identity. Direct MSH read and write still preserve every accepted serialized representation exactly.

This trades byte-exact MSH -> glTF -> MSH round trips for a smaller authoring interface, deterministic canonical output, and greater locality in MSH authoring modules. Missing typed metadata uses canonical authoring defaults, renaming a canonical identifier changes or removes its semantic target, and duplicate canonical identifiers are metadata conflicts rather than aliases.

glTF creation has no source mesh asset dependency: local envelopes retain typed values on canonical named owners, game resource bindings remain explicit creation options, and required unsupported semantics fail when no safe canonical default exists. Equivalent creation inputs produce identical bytes except for a newly generated archive creation GUID. The cutover removes source-based edit machinery, interchange identities, projection fingerprints, preservation reports, and export receipts rather than retaining compatibility shims; MSH export warns when accepted source-only representations will be lost by later glTF creation.
